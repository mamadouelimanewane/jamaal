2. Sécurité — ce qui a été vérifié et jugé conforme

  • Actions d'administration : les 23 fonctions d'écriture (produits, consultants, coupons, retours, utilisateurs, paiements de commissions, réglages, visuels) commencent toutes par un contrôle d'accès administrateur.
  • Pages d'administration : préfixes réservés à l'administrateur dans src/proxy.ts ; les pages restantes (espace revendeur, assistant, notifications) ont leur propre garde.
  • Données d'autrui : une commande de revendeur n'est lisible que par son revendeur ; les protocoles signés sont limités à leur signataire et aux administrateurs.
  • Points d'entrée API sans session (testés en ligne) : exports, diagnostics, cron, relais Chogan, assistant d'administration, parrainage, promotions, visuels : tous refusés (401, 403 ou 405).
  • Webhooks : Wave, Orange Money, Stripe, Versus et WhatsApp refusent tout appel non signé (401 ou 503). Le webhook Versus relit le paiement chez Versus avant de valider.
  • Prix : le serveur recontrôle chaque prix de commande contre le catalogue (un client ne peut pas imposer un prix).
  • Limitation de débit : assistant de la boutique, paiement, commande ; verrouillage du compte après échecs de connexion.
  • Injection / XSS : les 11 requêtes SQL brutes sont toutes des gabarits paramétrés ($queryRaw avec valeurs liées, aucun Unsafe) ; le seul dangerouslySetInnerHTML (un script constant sur la facture d'administration, sans donnée utilisateur) a été remplacé par un composant : il n'en reste aucun ; aucun eval ni child_process hors tests.
  • En-têtes : CSP, HSTS (préchargement), X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy. Cookies d'authentification HttpOnly, Secure, SameSite=Lax.
  • Site en ligne : 27 pages publiques testées, aucune erreur serveur ; robots.txt exclut l'administration et l'API.

3. Corrections apportées pendant l'audit

  1. Tests : trois tests échouaient sous Windows (chemins C:\C:\… dans trois scripts d'import ; faux python3 du Microsoft Store dans le test ZIP). Corrigés : la suite passe de 3 échecs à 0.
  2. npm test n'exécutait aucun test sous Windows (guillemets simples) : corrigé, la commande fonctionne partout.
  3. Référencement : 12 pages publiques partageaient le même titre générique. Chacune a désormais un titre et une description propres (collections avec le nom de la catégorie ; panier et liste de souhaits exclus de l'indexation).
  4. La page de facture d'administration n'utilise plus de script en ligne (composant d'impression), un obstacle de moins à un futur CSP strict.
  5. Corrections des jours précédents : adresses de retour Versus en https, libellé de paiement, message de bienvenue, dépendances next 16.4.0 et sharp 0.35.5.

5. Ce qui n'a pas pu être vérifié

  • Les 21 tests qui exigent une base de données.
  • Les écrans connectés (administrateur, revendeur, livreur) : aucune session de test n'était disponible, donc les droits ont été vérifiés par lecture du code et par sondage sans session, pas par navigation réelle.
  • L'envoi réel de messages WhatsApp (prestataire non configuré, messages simulés).
  • Un paiement Versus de bout en bout et la réception réelle de son webhook.
  • Performance sous charge, accessibilité complète (lecteur d'écran), conformité juridique (RGPD / droit sénégalais).
